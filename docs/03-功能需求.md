# Reliability Flow Agent 功能需求

本文档将系统功能拆分为可开发、可测试的需求项。状态仅反映当前已知项目基础，开发过程中应根据代码和测试证据更新。

## 状态定义

- **已有基础**：相关后端或前端能力已存在，但仍需按验收标准核验完整性。
- **部分具备**：已有局部实现，尚未形成完整业务闭环。
- **规划中**：目标能力，当前尚未完成。
- **待确认**：业务规则尚未定稿，不能据此直接实现最终行为。

## FR-01 需求输入与会话交互

**状态：部分具备**

系统应允许用户通过 Web 界面提交建模需求，并查看 Agent 对需求的反馈。

验收标准：
- 用户可提交多轮文本需求。
- 前端能够展示用户消息、Agent 消息及工具执行状态。
- 消息与会话具有稳定关联。
- 后端异常、超时和断连能够被明确展示。

当前差距：已有 AgentPanel，但主要由前端本地规则解析驱动；后端聊天 API、Session 管理和流式通道尚未形成完整实现。

## FR-02 需求信息抽取

**状态：规划中**

Agent 应从需求文本中提取装备/设备实体、任务活动、持续时间、流程关系、资源、可靠性参数和运行配置。

验收标准：
- 抽取结果使用结构化字段表达。
- 每项信息标记来源或原文依据。
- 明确区分原文事实、系统推断和待确认项。
- 缺少关键参数时提出澄清问题，不得自行编造。

## FR-03 Process IR 生成与编辑

**状态：已有基础，Agent 自动生成闭环待建设**

系统应支持 Process IR 的结构化表示、校验、查看和编辑。

验收标准：
- 节点及连接关系具有稳定标识。
- 支持需求所需的顺序、条件分支和循环表达。
- 引用不存在的节点或非法连接应被校验器拒绝。
- 模型修改后能够识别版本或内容变化。
- Agent 生成的内容先作为草稿，不直接覆盖正式模型。

## FR-04 Reliability IR 生成与管理

**状态：已有基础，Agent 自动生成闭环待建设**

系统应支持可靠性参数定义，并将 Reliability IR 与对应 Process 版本或内容哈希绑定。

验收标准：
- 可靠性参数具有明确对象、单位和取值约束。
- 缺失、非法或无法关联的参数产生明确校验错误。
- Process 模型变化后，能够识别 Reliability IR 关联是否仍然有效。
- Agent 不得为满足校验而伪造可靠性参数。

## FR-05 模型校验

**状态：已有基础**

系统应提供后端模型校验能力，并将校验结果反馈给前端和 Agent。

验收标准：
- 校验结果由后端接口真实返回。
- 错误信息能够定位到模型或字段。
- 校验失败时不得进入正式仿真。
- Agent 对校验结果的总结不得改变原始错误含义。

## FR-06 用户确认与模型保存

**状态：部分具备/需完善审批闭环**

系统应在正式保存模型前向用户展示模型内容和变更摘要，并要求用户明确确认。

验收标准：
- 未确认时不执行正式保存。
- 用户确认的对象、版本和内容应明确。
- 保存失败时反馈真实错误。
- Agent 不能仅凭自然语言中的模糊表达推定用户已批准。

## FR-07 仿真配置与执行

**状态：已有 Runtime 基础，Agent 审批闭环待建设**

系统应支持配置实体数量、仿真时长、随机种子等运行参数，并在用户确认后执行仿真。

验收标准：
- 运行配置经过后端校验。
- `entity_count` 表示仿真实体数量。
- 不得将实体数量自动解释为 Monte Carlo replication 次数。
- 运行状态和执行结果来自 Runtime。
- 未经用户明确确认不得启动仿真。

## FR-08 故障、维修与抽样规则

**状态：部分具备/业务细节待确认**

当前业务决策：
- 故障维修策略：`repair`；
- 故障抽样策略：`daily`；
- 流程关系：`configurable`。

验收标准：
- 实现行为与最终确认的业务规则一致。
- 对故障、维修开始、维修完成及状态恢复等事件提供可测试定义。
- daily 抽样时点和边界行为有明确规范。
- 维修期间故障暴露、维修资源和仿真结束边界等行为有明确规范。
- 不得将未确认的规则静默固化为默认行为。

## FR-09 结果评估与解释

**状态：已有基础**

系统应基于 Runtime 真实输出计算整体、节点和设备层面的指标。

当前提出的设备指标：
\[
R=1-\frac{N_{\text{ever-failed}}}{N_{\text{total}}}
\]

\[
A=\frac{N_{\text{operational at end}}}{N_{\text{total}}}
\]

验收标准：
- 指标分子、分母和统计时点有明确定义。
- 结果可追溯到对应运行记录和模型版本。
- 评估结果包含必要的警告和解释。
- Agent 不得生成 Runtime/Evaluation 未返回的数值。

## FR-10 仿真结果持久化与实验历史

**状态：规划中**

系统应支持保存仿真运行记录、结果标识和实验历史。

验收标准：
- 每次运行具有独立 result ID 或 run ID。
- 能够查询运行配置、模型版本、状态和评估结果。
- 能够区分运行中、成功、失败和取消等状态。
- 历史记录可关联发起会话和任务。
- 数据持久化失败时不能向用户报告保存成功。

## FR-11 Agent 任务生命周期管理

**状态：规划中**

系统应支持 Agent 任务创建、状态查询、取消、审批和历史查看。

验收标准：
- Task 有唯一标识和明确状态机。
- 工具执行开始/结束事件可追踪。
- 取消操作能够反馈真实执行状态。
- 需审批操作在批准前不得执行。
- 前端刷新或重连后可恢复任务状态。

## FR-12 端到端可观测性

**状态：规划中**

系统应记录需求输入、模型草稿、校验调用、审批决定、仿真运行和评估结果之间的关联。

验收标准：
- 日志中不泄露密钥或敏感凭据。
- 关键步骤具有时间戳和关联 ID。
- 错误能够定位到具体阶段。
- 重要结果能够通过测试或记录复现。
